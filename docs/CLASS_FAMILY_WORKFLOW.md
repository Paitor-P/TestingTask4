# Пересчёт вложенных классов и добавление повторов

Команды выполняются из `C:\Users\user\Documents\Polytech\Testing\Lab4up` в PowerShell.
Рабочий каталог Qwen остаётся прежним:
`src/generatedTest/qwen-v4-20260908-020700-5fa27f`.
Модель, промпты и правила генерации v4 не меняются.

## Первый пересчёт

```powershell
cd C:\Users\user\Documents\Polytech\Testing\Lab4up
.\scripts\research.ps1 -Action measure -Seeds 101
```

Будут измерены **12 готовых наборов**: четыре класса для каждого из EvoSuite,
Randoop и QwenLLM. У первых двух инструментов выбирается бюджет 120 секунд,
у Qwen — существующие наборы с защитным пределом 1800 секунд. Новая генерация
не запускается. Модель Ollama для измерения не нужна.

Область `class-family` включает точное имя внешнего класса и все бинарные имена
с префиксом `ИмяКласса$`: вложенные, локальные и анонимные классы.
Соседние классы вроде `ИмяКлассаHelper` не включаются. JaCoCo суммирует счётчики
всех классов семейства, а PIT получает два шаблона: точное имя и `ИмяКласса$*`.
Проценты отдельных классов не усредняются. Единица строки — пара
«бинарное имя класса, номер строки»; совпавшие номера строк разных классов
считаются отдельными координатами.

Данные сохраняются в новом каталоге `reports/data/family-measure-<время>/`:

- `workflow.log` — команды и вывод;
- `comparison.csv` — показатели всех выбранных наборов;
- `scope-checks.json` — реально найденные JaCoCo-классы и мутированные PIT-классы;
- `completion.json` — успешное завершение проверки;
- `quality/` — подробные CSV исходных анализаторов.

Старые отчёты внешних классов и их результаты сборки не перезаписываются.

## Когда переходить к дополнительной генерации

Дождитесь **`CLASS FAMILY CHECK PASSED: 12 suites, 0 empty`** и возврата приглашения
PowerShell. Эта строка означает, что скрипт проверил:

1. Все 12 наборов присутствуют и успешно проанализированы.
2. Число выполнений тестов совпадает с прежними результатами; нет ошибок и пропусков.
3. Все четыре метрики рассчитаны в новой области.
4. JaCoCo видит все скомпилированные классы семейства, включая невыполненные.
5. PIT действительно мутировал `SimpleJsonParser$Parser` и `LruCache$1`, а посторонние
   классы не попали в анализ.

**Не нужно ждать роста покрытия или определённого mutation score.** После добавления
непокрытого кода проценты могут снизиться — это результат измерения, а не ошибка.
При `WORKFLOW FAILED`, исключении или отсутствии маркера не переходите дальше:
сохраните путь к `workflow.log`. Повторную генерацию для «исправления» низких метрик
или пустой серии выполнять не следует.

## Добавить ещё два повтора

После успешной проверки выполните:

```powershell
.\scripts\research.ps1 -Action extend -Seeds 202,303
```

Это восемь новых серий Qwen: два seed для каждого из четырёх классов.
Существующий seed 101 используется как первый повтор, его тесты не меняются.
Оценка дополнительного времени по первой серии — около 2 часов 49 минут;
защитный предел — 4 часа плюс подготовка.

Команда перед стартом сверяет сохранённую проверку измерений, версию адаптера,
настройки модели и хеши исходников. Серии сохраняются в **тот же корень Qwen**.
Завершённые сочетания «класс, seed» пропускаются, включая честно завершённые EMPTY.
При прерывании между сериями повтор команды выполнит недостающие.
Неполная, повреждённая или FAIL-серия вызывает явную остановку, а не скрытую замену:
в таком случае нужен разбор журнала с сохранением исходного аудита.

Конечный маркер — **`QWEN EXTENSION FINISHED`**.
Он означает, что все запрошенные серии завершены, но не обещает по 10 тестов в каждой.
После него можно сразу пересчитать все доступные повторы:

```powershell
.\scripts\research.ps1 -Action measure
```

Без `-Seeds` выбираются все завершённые Qwen seed в рабочем каталоге и соответствующие
серии двух исходных инструментов. После добавления seed 202/303 ожидаются **36 наборов**.
EMPTY сохраняется отдельным исходом с отсутствующими метриками, а не PIT=0;
маркер завершения показывает число пустых наборов. Частичный набор со статусом OK
оценивается целиком. Инфраструктурные ошибки блокируют успешное завершение.

## Спектры выполнения

Первый пересчёт намеренно ограничен JUnit, JaCoCo и PIT: этого достаточно для
технической проверки области перед расширением генерации. Для спектров используется
тот же набор классов и фиксированный порядок координат «имя класса, номер строки».
Даже незагруженные вложенные классы дают нулевые координаты. Рядом с CSV сохраняется
`*.schema.json` со списком координат и хешем исходника. Смешивание старых и новых
спектров или несовпадение координат блокируется.

Чтобы после генерации трёх повторов также пересобрать спектры и сходство трёх пар:

```powershell
.\scripts\research.ps1 -Action measure -WithTraces
```

Эта команда повторно измеряет качество и дополнительно собирает спектры для всех
трёх инструментов. Каждый тест выполняется в отдельной JVM; у Randoop тысячи
методов, поэтому этот этап может быть существенно дольше обычного пересчёта.
Можно сразу использовать его вместо предыдущей команды, если нужен полный анализ.
Старые спектры внешних классов не переиспользуются для новой области.

В новой сводке `testsExecuted` — число выполнений, а `uniqueTestMethods` — число
различных пар JUnit classname/name. У Randoop общий suite-runner может запускать
одни методы повторно; спектр записывается один раз на метод и сверяется именно
с `uniqueTestMethods`. Сравнение семейств связывает наборы по классу, seed и
reference-конфигурациям, а не требует одинакового номера папки run.

## Если позже понадобятся дополнительные повторы

Например, для пяти повторов на класс:

```powershell
.\scripts\research.ps1 -Action extend -Seeds 404,505
.\scripts\research.ps1 -Action measure
```

Переписывать скрипты или заново генерировать первые три повтора не требуется.
Если в список случайно включить уже готовые seed, они будут пропущены.
В исходном исследовании доступны seed 101, 202, 303, 404, 505, 606, 707, 808, 909,
10010. Для другого seed сначала нужны соответствующие готовые наборы EvoSuite
и Randoop; отсутствие этих данных будет обнаружено до запуска Qwen.

На другой машине путь к JDK 17 задаётся через `-JavaHome`, а другой корень уже
созданного однородного эксперимента — через `-Suites`. Смена модели, промпта,
настроек генерации или исходников требует отдельного эксперимента: старые повторы
нельзя молча объединять с новой конфигурацией.

`run_qwen_v4.ps1` остаётся командой создания новой проверки seed 101;
для продолжения этой серии используйте именно `research.ps1 -Action extend`.
`measure_qwen_v4.ps1` сохранён для воспроизведения прежней области внешних классов.
