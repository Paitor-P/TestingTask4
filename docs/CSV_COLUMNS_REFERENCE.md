# CSV-файлы и методика агрегации

Исходные результаты экспериментов хранятся в `reports/data/`. Часть имени после
двойного подчёркивания фиксирует применённые фильтры, например
`__tools-EvoSuite__cases-all__budgets-30-60__runs-all`.

## `generation_runs.csv`

Одна строка соответствует одному запуску генератора. Столбцы `tool`,
`targetClass`, `budgetSec`, `run` и `seed` идентифицируют запуск; `elapsedSec`
содержит фактическое время, `outputDir` — каталог набора тестов, `status` и
`error` — результат выполнения. Dry run записывается отдельно в
`generation_runs_dry_run.csv`, чтобы предварительный просмотр не смешивался с
измерениями.

## `quality/quality_runs__...csv`

Одна строка соответствует одному набору `(tool, case, budgetSec, run, seed)`.

- `generatedTestFiles` — число исходных файлов Java, а `testsExecuted`,
  `testFailures`, `testSkipped` — счётчики из JUnit XML. Один файл может
  содержать много тестовых методов, поэтому эти величины не обязаны совпадать.
- `lineCoveragePct`, `branchCoveragePct`, `instructionCoveragePct` — доля
  покрытых счётчиков целевого класса по JaCoCo: `covered / (covered + missed)`.
  Счётчики других классов в процент не входят.
- `mutationScorePct` — `mutationsKilled / mutationsTotal * 100` для данного
  запуска. `mutationsSurvived`, `mutationsTimedOut` и `mutationsNoCoverage`
  сохраняются отдельно.
- `generationElapsedSec` берётся из `generation_runs.csv`, а
  `analysisElapsedSec` измеряет полный прогон JUnit, JaCoCo и PIT.
- `sourceDir` указывает на неизменённый набор генератора, `preparedDir` — на
  временную нормализованную копию в `build/analysis/work/`.

## `quality/quality_summary__...csv`

Строки с `status != OK` исключаются. Оставшиеся запуски группируются по
`(tool, case, budgetSec)`: разные бюджеты никогда не смешиваются. Каждый запуск
имеет одинаковый вес.

Для каждой метрики записываются размер доступной выборки (`testsSamples`,
`lineSamples`, `branchSamples`, `instructionSamples`, `mutationSamples`),
арифметическое среднее, выборочная дисперсия, выборочное стандартное отклонение
и границы 95-процентного доверительного интервала среднего. Пропуск конкретной
метрики исключается только из её выборки, поэтому `runs` и `...Samples` могут
различаться.

Мутационный показатель агрегируется как среднее процентов отдельных запусков:

`meanMutationScorePct = mean(killed_i / total_i * 100)`.

Это даёт одинаковый вес каждому независимому запуску. Показатель намеренно не
равен `sum(killed_i) / sum(total_i)`: последний дал бы больший вес запускам, для
которых PIT создал больше мутантов.

Для выборки `x_1, ..., x_n` используются формулы:

- среднее: `x̄ = sum(x_i) / n`;
- выборочная дисперсия: `s² = sum((x_i - x̄)²) / (n - 1)`;
- стандартное отклонение: `s = sqrt(s²)`;
- интервал среднего: `x̄ ± t(0.975, n-1) * s / sqrt(n)`.

Для 1–30 степеней свободы используются табличные критические значения
распределения Стьюдента, для больших выборок — нормальное приближение `1.96`.

При `n = 1` среднее равно единственному наблюдению, а дисперсия и доверительный
интервал не определяются. При `n = 0` не определяется и среднее. Интервал
основан на независимости запусков и приближённой нормальности распределения
среднего. 95% относится к долгосрочному покрытию интервалов при повторении
эксперимента; это не вероятность нахождения фиксированного истинного среднего
в уже вычисленном интервале. Перекрытие или неперекрытие двух интервалов само по
себе не заменяет статистический тест разности.

## `traces/*_test_traces.csv`

Одна строка — один тестовый метод. `coverage_vector` является бинарным вектором
покрытия строк целевого класса; `program_class`, `generation_time_sec`, `run` и
`seed` связывают трассу с запуском. Подробная методика сравнения приведена в
[similarity_pseudocode.md](similarity_pseudocode.md).

## `similarity/`

- `similarity_runs__...csv` содержит симметричное сходство для каждого запуска:
  `mean_max_*` — среднее двух направлений, а `evosuite_to_randoop_*` и
  `randoop_to_evosuite_*` — диагностические значения каждого направления;
- `similarity_summary__...csv` усредняет симметричное сходство по запускам и содержит выборочную
  дисперсию, стандартное отклонение и 95-процентный интервал;
- `exclusive_coverage_runs__...csv` содержит число общих и уникально покрытых
  строк для каждой пары наборов.

В `similarity_summary` поле `runs` — число сопоставленных запусков, а `samples`
— число конечных значений, фактически вошедших в статистику. Они различаются,
если в запуске отсутствуют оба набора тестов и сходство равно `NaN`.

Таблицы отчёта, объединяющие несколько бюджетов, вычисляют среднее по уже
полученным средним каждого бюджета. Таким образом, каждый бюджет имеет
одинаковый вес независимо от числа доступных запусков. Такие таблицы подходят
для обзорного описания, а выводы о влиянии бюджета следует делать по строкам
отдельных бюджетов.
